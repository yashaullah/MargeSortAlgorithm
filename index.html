    How Merge Sort works

    1. Call MERGE-SORT(A, p, r) with the array A and the indices p (start) and r (end).
    2. Check whether the sub-array has more than one element (p < r).
    3. Divide: find the middle index q = ⌊(p + r) / 2⌋.
    4. Conquer left: recursively sort the left half A[p..q].
    5. Conquer right: recursively sort the right half A[q+1..r].
    6. Combine: merge the two sorted halves into one sorted array.
    7. Stop the recursion when a sub-array has 0 or 1 element, because it is already sorted.

    How two sorted halves are merged

    Keep one pointer at the front of each half. Compare the two front elements, move the smaller one to the output and advance that pointer. When one half runs out, copy whatever is left of the other half.

    If the two elements are equal, the one from the left half is taken first. This is why Merge Sort is a stable sort.

    Time complexity

    Choose a case to see its time complexity. The same choice exists in the Windows Forms application.

    Why every case is O(n log n)

    The running time follows the recurrence

    T(n) = 2·T(n/2) + Θ(n)

    The array is halved at each level, so there are about log2 n levels. At every level the merges touch all n elements once. That gives n × log2 n work. The input order only changes how many comparisons happen inside a merge, never how many levels there are or how many elements are copied.

    Key points

    • Follows the Divide and Conquer approach.
    • Time complexity: O(n log n) in the best, average and worst case.
    • Space complexity: O(n), because the merge step needs a temporary array.
    • A stable sorting algorithm.
    • Works well for large data sets, and the speed does not depend on the input order.
